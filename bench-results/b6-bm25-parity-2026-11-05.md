## The NFCorpus and TREC-COVID gap

Checked one by one, all ruled out as causes:

- **Qrels and queries:** identical to Anserini's `qrels.beir-v1.0.0-*.test.txt` and `topics.beir-v1.0.0-*.test.tsv.gz` (TREC-COVID's file only drops two rows graded -1, which score the same).
- **Index stats:** doc counts equal Anserini's. Total terms differ by under 0.07%: Lucene keeps `©`, `®` and `™` as tokens (telusur drops them) and drops `²` or `½` (telusur keeps them). Matching Lucene on those symbols moves NFCorpus by 0.01 and TREC-COVID by 0.00.
- **Metrics:** telusur's run files rescored with pytrec_eval (trec_eval's own code) give the same numbers. Treating run scores as 32-bit floats, as trec_eval did before 2023, changes nothing.
- **Lucene itself:** plain Lucene 10.5.0 (the version Anserini pins) with Anserini's analyzer chain, BM25 k1 0.9 b 0.4, one boosted clause per query term, top 1000 and query id removal scores NFCorpus 32.06 and TREC-COVID 59.35, the same as telusur.

So telusur matches Lucene 10.5. The remaining 0.12 to 0.13 is between that setup and Anserini's published numbers, which were recorded with Lucene 8.11.0 in April 2022 and have not changed since. Anserini itself was not run.
